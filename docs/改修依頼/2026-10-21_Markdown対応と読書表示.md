# AgilNote 改修依頼 AN-001：Markdown対応と安全な読書表示

- **依頼日**：2026-10-21
- **依頼先**：Claude（AgilNote実装担当）
- **状態**：**実装済み**（2026-10-21、agilnote-v2）／変更履歴：2026-10-21 依頼書登録 → 同日 実装
- **対象**：次回以降のバージョンアップ（版番号は実装時に確定）
- **対象リポジトリ**：AAA0108/AgilNote
- **背景**：AIに執筆させた小説、とくにMarkdownを正本として保管する長編小説を、AgilNoteで直接・快適に読むための改修。

## 1. 目的と優先順位

**第一目的は、小説の本文・演出・判定表示・話末の選択肢を欠落させず、原稿に忠実な読書表示を作ること。**
Markdownの構文記号だけを適切に表示へ変換し、不要な内部メモがある場合に限り安全・可逆的に非表示にする。

優先順位は以下。
1. **情報の非欠落・原文の保護**：必要な文字・段落・選択肢を誤って消さない。読み込んだ原稿を絶対に書き換えない。
2. **小説としての組版**：地の文の段落、台詞の改行、全角字下げ、場面転換、ルビ、縦書きと横書きを維持。
3. **Markdown構文の読書向け描画**：見出し・強調・表・リストなどをそのまま読める形にする。
4. **可逆的な内部記録の非表示**：明示的な範囲だけを読書モードで隠し、必要なら全文を表示できる。
5. **統計の正確性**：本文・台詞・System・内部記録等を混同しない。厳密な分類ができない部分を恣意的に捨てない。

機能を増やすこと自体は目的ではない。既存の良い操作感を維持し、最小限で実装する。

## 2. 現行実装の確認事項

2026-10-21時点の main を前提に、着手時は最新版を再確認すること。

- 現行は単一の \`index.html\` にレンダリング・操作・統計があり、\`render()\` が本文を行単位で \`<p>\` にする。行頭を使ったタイトル／場面区切りの識別、\`inline()\` のルビ・縦中横、\`stats()\` の文章統計がある。
- 入力は \`.txt\`、貼り付け、ドラッグ＆ドロップ、Windowsのファイルハンドラ。UTF-8／Shift_JIS、横書き／縦書き、３つの表示プリセット、フォント追加、ローカル保存、オフラインPWAに対応。
- \`manifest.webmanifest\` は \`text/plain\` の \`.txt\` を登録している。更新時には \`sw.js\` の \`VERSION\` を更新する運用。
- 現行仕様ではMarkdownの \`#\`、\`**\`、\`|\` 区切りの表等は書式として解釈されず文字列として読まれる。
- 現行の統計は原文の非空行と行頭の括弧から算出するため、Markdown表やSystem一覧を地の文として数えてしまう。

関連箇所：\`README.md\`、\`index.html\`（\`inline\`／\`render\`／\`stats\`／\`loadFile\`／\`PRESETS\`）、\`manifest.webmanifest\`、\`sw.js\`。

## 3. 必須機能 A：Markdownを直接開く

### 入力

- \`.md\`、\`.markdown\` の読み込みを追加。ファイル選択、ドラッグ＆ドロップ、対応可能な環境のOSファイルハンドラで扱う。\`.txt\` は引き続き**プレーンテキスト**として従来通り表示する。
- 拡張子でMarkdown／TXTを判別。貼り付けテキストは判別を押しつけず、少なくとも利用者が「プレーンテキスト／Markdown」を選べるようにする（UIは最小限でよい）。
- 既存のUTF-8／Shift_JIS判定、文字コードの再選択、端末内だけで処理する仕様を維持。元の入力文字列を保持し、表示操作で元データを破壊しない。

### 表示に必要なMarkdown

まず小説本文で必要な次の構文を正しく扱う。

| 構文 | 読書画面 |
|---|---|
| \`#\` ～ \`######\` 見出し | レベルを保った見出し。冒頭の「第○話」を自然に表示 |
| \`**太字**\`、\`*強調*\`、\`~~取消~~\` | 書式を反映し、構文記号を読書本文へ出さない |
| \`---\` 等の水平線 | 場面の切り替えに適した区切り |
| \`- 項目\`／番号付きリスト | 原文の項目・順序を保って表示 |
| GitHub Flavored Markdownのパイプ表 | 表として表示。セルの内容、数値、列、行を欠落させない |
| 引用 \`>\` | 区別して表示 |
| インラインコード／コードフェンス | 内容を文字どおり表示。内部のMarkdownやルビ記法を再解釈しない |
| リンク | リンク文字列を保持して安全に扱う。危険なURLスキームを実行しない |
| \`｜漢字《かんじ》\`、\`|漢字《かんじ》\`、\`漢字《かんじ》\` | 既存のルビ表示を維持 |
| \`≪System≫\`、\`【判定】\`、話末アンケート | **本文として必ず表示**。勝手に内部メモ扱いしない |

**重要：小説の改行は一般的なMarkdown段落結合とは別ルール。**

- 地の文一行、台詞一行を一つの表示段落として扱う**現行の読書上の改行感覚**を維持する。
- 次の２行をMarkdownのソフト改行だからといって一つの段落へ結合しない：\`「こんにちは」\` と次行の \`「おはよう」\`。
- 全角空白 \`　\` の段落冒頭字下げ、原稿の空行、既存の「空行を詰める」設定を尊重する。ただしリスト／表／コードフェンス内部の行を通常の小説段落と誤認しない。
- Markdown見出しが冒頭にあるときに現行の「最初の行を自動的にタイトル化する」規則と二重適用しない。縦書きで見出し・表が壊れたり重なったりしないようにする。
- 既存の縦中横（２桁数字・「！？」等）は通常の可視テキストで維持し、コードやURL／既存ルビの内部を不正に加工しない。

**縦書きの表**は横組みの独立ブロックやスクロール領域にするなど、内容が読み取れる方式を採用してよい。表を削除したり、一行へ潰したり、列を失わせたりする方式は不可。

Markdownパーサーの採用／内製や構造はClaudeの裁量。ただし全構文を無理に手書き正規表現で一括置換することによる構造破壊を避ける。依存ライブラリを使うならライセンスを確認し、PWAのオフライン表示に必要なコードを**ローカル同梱**すること。読書のたびに外部CDNへ接続する構成にはしない。

## 4. 必須機能 B：安全で可逆的な非表示

### 原則

- **自動推測で本文を隠さない。** \`## 次月への引き継ぎ\`、\`≪System≫\`、\`【アンケート】\`、リザルト、表、コメントらしい文章という理由だけでは非表示にしない。
- 非表示はAgilNote専用の**明示的な境界**がある場合に限る。元Markdownから削除せず、表示の切替だけを行う。
- 「読書表示」（初期値）と「全文表示」の切替を設ける。全文表示では非表示指定部分の内容も読める。読書表示中に隠れている内部情報があることを控えめに示してもよい。
- 通常のMarkdown HTMLコメントや未知の命令を、AgilNote用の境界と取り違えない。入力に含まれる文字・内容が必要なら確認可能にする。

### マーカー案（この表記を基本とする）

\`\`\`md
# 第7話　新しい朝

　小説本文が続く。

≪System≫
成功／スピード＋10

【アンケート】
次は何を鍛える？

<!-- agilnote:internal:start -->
## GM向け次話引継ぎ
次月の未処理事項、内部判断理由など。
<!-- agilnote:internal:end -->
\`\`\`

- 開始と終了は**単独行の完全一致**（前後の許容空白は最小限）で判定する。恣意的な部分一致・見出し名による非表示を行わない。
- 対応する開始／終了が揃っている範囲のみ非表示。片側が欠ける、逆順、入れ子、重複などの不正マーカーでは**隠さず**警告する。特に終了マーカーがないからといって以降の本文やアンケートを最後まで隠してはいけない。
- コードフェンス／インラインコード／エスケープ表示内に登場した同じ文字列は**マーカーとして認識しない**。
- \`.txt\` は原則プレーンテキスト表示のまま。TXTに同じ文字列が現れても既定で非表示にしない。
- 未知のHTML、危険なURL、入力内容由来のスクリプトは実行しない。**表示上の隠蔽とセキュリティ上のサニタイズは別機能**として実装する。HTMLは既定では無害な文字列として表示するなど、安全側で扱う。
- 「全文表示」は整形済みMarkdown表示でよい。必要であれば原文表示の導線を追加してもよいが、今回の必須条件は**元データ非変更と隠した内容へのアクセス**である。

既存のファイルはマーカーがないので、従来どおり**全文が表示される**こと。作品側へマーカーを強制追加しない。

## 5. 必須機能 C：文章統計

既存の「文字数／段落／台詞段落率／地の文の平均字数／12字以下の地の文」を維持する。ただしMarkdownを単純な原文行として数えず、**実際に表示する読書テキスト／構造**を参照して計算する。

- Markdown記号（\`#\`、\`**\`、表の \`|\`・区切り線など）は本文字数に加算しない。
- 見出し・表・リスト・コードブロック・明示的な内部範囲は、少なくとも**地の文平均長や短文地の文数へ混入させない**。その分類根拠が不足するテキストを推測で削除せず、必要なら「その他」として計測する。
- 読書表示で隠した範囲は読書本文の統計から除外。全文表示では原文全体の統計へ切り替えるか、内部範囲を別集計にする。どちらかの意味をUIで明記する。
- \`≪System≫\`以下のブロックを見出し名や類似語だけで勝手に削除しない。Systemを独立集計するなら、安全に範囲が判定できる明示分類／構造を用いる。**読書画面では必ず残す**。
- TXT読み込みでは既存統計の意味と数値が不必要に変化しないようにする。
- 統計は文章の品質の**参考情報**であって、短文・台詞そのものを禁止したり元原稿を自動修正する機能ではない。

## 6. テスト・受入（実装完了の条件）

**実装担当は、実際に表示した画面で横書き／縦書き／各プリセットを確認すること。** パーサーの文字列試験だけで完了としない。可能なら最小の自動試験を設ける。

| ケース | 合格条件 |
|---|---|
| 従来の \`.txt\`、ルビ、字下げ、場面区切り | 旧来と同じ内容・改行で読める |
| \`.md\` ファイル選択／ドロップ／貼り付け | Markdownとして読み込め、TXT切替も可能 |
| ２行連続の台詞と長い地の文、途中の空行 | 台詞が連結しない。段落・空行・字下げが失われない |
| \`#\` 見出し、\`**強調**\`、\`---\`、リスト、表 | 構文記号が読書表示に露出せず、意味と値がすべて残る |
| ルビ・コード・表・縦中横の組合せ | 意図した箇所だけに書式が適用される |
| Systemの出目・ステータス表・話末アンケート | 読書表示でも**全文残る**。結果や選択肢が欠落しない |
| 正しい内部マーカー１組 | 読書表示でその部分だけ非表示、全文表示で復元 |
| 不正なマーカー（片側欠落・入れ子・逆順） | **本文を隠さず警告**する。後続内容が消失しない |
| コードフェンス中／通常テキストのマーカー文字列 | 内部マーカーと誤認しない |
| HTML/リンクの悪意ある入力 | JavaScript実行・HTML注入が起きず、内容を安全に確認できる |
| 縦書きの幅の広い表・スマホ表示 | セルを欠落させず、横組み等の読める代替表示 |
| 統計（小説段落とMarkdown表、内部マーカー） | 表や非表示内部記録の混入を避け、数値の意味をUIで理解できる |
| オフライン起動／追加フォント／暗色／ファイルハンドラ | 既存機能が退行しない |

テスト原稿は**合成の短いサンプル**で用意する。外部の私有小説データ・非公開リポジトリの本文を、この公開リポジトリへ複製しないこと。

## 7. 実装と提出の運用

- 既存の \`index.html\`、\`manifest.webmanifest\`、\`sw.js\`、\`README.md\` を必要範囲で変更。設計上有利であれば小さなJS/CSS資産・テストを追加してよい。
- \`sw.js\` の \`VERSION\` を実際のアプリ更新時に上げ、オフライン動作と更新反映を検証。**依頼書を追加しただけではアプリのバージョンは上げない。**
- READMEにMarkdown対応、表示切替、マーカー書式、入力方法、オフラインでの利用条件を反映。
- 本文・ファイル・フォントが外部に送信されない従来方針を維持（必要なオンラインフォント取得等の既存挙動は区別して説明）。
- 実装完了後、**この依頼書の状態を「実装済み」に更新**し、実装コミットSHA・リリース/版・実施したテストと未対応事項を追記する。依頼当初の要求・日付は削除せず、変更履歴として残す。
- 完了報告は「何が動くようになったか／従来の何を守ったか／実機確認と不具合／未対応／コミットURL」を簡潔に記す。
- 根拠のない自動削除・コンテンツの補完・原稿ファイル自体の書換えは行わない。今回依頼していない動画・音声・クラウド同期などの大型機能は増設しない。

#### 何が動くようになったか

- `.md`／`.markdown` をファイル選択・ドロップ・Windows のファイル関連付けで開ける。拡張子で形式を自動選択し、上部の「形式」欄で TXT と Markdown を切り替えられる。貼り付けは「プレーンテキストとして／Markdownとして」を選ぶ。
- Markdown 描画は `md.js` に内製（外部ライブラリ・CDN なし、本体と一緒にオフライン保存）。行を種類ごとに読み分けるブロック解析と、記号を一文字ずつ読む行内解析で、一括の正規表現置換はしていない。
- 本文は 1 行 1 段落。見出し、太字、強調（傍点）、取消、水平線、リスト（入れ子・番号）、GFM の表（揃え・列数不一致はセルを捨てずに最大列へ揃える）、引用、コード、リンク、ルビ、縦中横に対応。
- 内部記録マーカーは単独行の完全一致・フェンス外のみ有効。不整合が一つでもあれば何も隠さず、行番号つきで警告する。読書表示では「内部記録を非表示」と小さく示し、全文表示では点線の枠で表示。
- HTML はすべて文字として表示。リンクは http/https/mailto のみ有効、それ以外は文字として残し、どこにも飛ばない。画像は読み込まず「［画像：説明］」と表示。
- 統計（Markdown）：文字数は表示文字、段落系の指標は本文段落のみ、見出し・表・リスト・引用・コードは「その他」、内部記録はどちらの表示でも統計外（件数のみ表示）。

#### 従来の何を守ったか

- `.txt` は従来の処理をそのまま使用。改善前の作品（409段落）で、旧版と新版の本文 HTML と統計が横書き・縦書きとも完全一致することを確認。
- 端末内だけで処理する方針、文字コード判定、追加書体、明暗、表示プリセット、オフライン動作。

#### 実施した確認

- 自動試験 `node tests/md.test.js`：19件すべて合格（台詞の非連結、空行と字下げ、記号の非露出、リスト順序、表の非欠落、System・アンケートの残存、正しいマーカー、終了なし・入れ子・逆順の不正マーカー、フェンス内・文中のマーカー、HTMLとリンクの無害化、ルビ、コード内の非解釈、縦中横の適用範囲、エスケープ、場面区切り ほか）。
- 実画面（Chromium）：`samples/markdown-sample.md` を横書き・縦書き・全文表示・スマホ幅（390px）＋暗色・投稿サイト風／チャット画面風／文庫風で表示し、横方向のはみ出しがないこと、表とコードが縦書きで横組みの枠として読めることを確認。
- 公開版（GitHub Pages）で本体・`md.js`・manifest・sw の配信を確認。

#### 実装中に見つけて直した不具合

- 縦書きに切り替えたとき、文書の末尾から表示されていた（旧版からの不具合）。読み始めを右端（冒頭）に合わせ、設定の変更では位置が飛ばないようにした。

#### 未対応・制限

- 見出しの下線形式（setext）と、4 字下げのコードブロックは非対応。小説の `---`（場面転換）や半角空白の字下げを誤って解釈しないため。
- 表のセル内で半角 `|` を使ったルビは列の区切りになる。全角 `｜` を推奨（README に記載）。
- Windows で `.md` の関連付けが加わるのは、更新後にアプリを開き直してから。加わらない場合は入れ直しが必要。iOS はファイル関連付け非対応（従来どおり）。
- 実機の Windows／スマホでのインストール後の動作は、利用者側の確認待ち。
