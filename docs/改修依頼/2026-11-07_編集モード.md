# AN-002：編集モード（実装記録）

- 日付：2026-11-07
- 依頼：ユーザーから Claude へ直接（改修依頼書なし）
- 版：agilnote-v4

## 依頼の内容

- 読書モードと編集モードを切り替えるボタンを付ける
- 編集モードでは紙面の文字を直接書き換えられ、保存ボタンで反映する
- 編集によって原文から変わった部分は背景色が変わって分かるようにする

## 決めたこと

| 項目 | 決定 | 理由 |
|---|---|---|
| 編集面 | 原文（ルビ記法・Markdown記号を含む）をそのまま、読書と同じ書体・大きさ・向きで表示して編集 | 整形後の表示を直接編集すると、ルビの漢字と読みの境目や Markdown の構造が壊れやすい |
| 反映の時期 | 保存したときだけ、ファイルと読書表示に反映 | 「保存ボタンで反映」という依頼どおり。書きかけは編集面に残す |
| 色分け | 書き換えた段落＝薄い黄、足した文字＝濃い黄、消した場所＝赤い波線 | 段落単位で探しやすく、その中で何を変えたかも分かるように |
| 比べる相手 | 最後に開いた／保存した内容 | 保存したら色を消し、それを新しい原文にする |
| 保存先 | 開いたファイルに上書き → 保存先を選ぶ画面 → ダウンロード | ブラウザが対応する範囲で上書き。スマホなどはダウンロード |
| 文字コード | 開いたときの文字コード・BOM・改行コード・末尾改行を保つ | Shift_JIS のファイルが UTF-8 に化けないように |

## 実装

- `edit.js`（新規）：画面に依存しない部分
  - `marks(原文の行, 編集後の行)`：行単位の差分 → 対応する行どうしは文字単位の差分。色を付ける範囲と変更か所の数を返す。前後の一致部分を先に除き、残りが大きすぎるときはまとめて「書き換えた」扱いにして固まらないようにした
  - `encodeSjis(文字列)`：ブラウザの Shift_JIS 読み取りから逆引き表を作って書き出す（WHATWG と同じく IBM 拡張の重複位置は使わない）。`〜−‖—¢£¬` は見た目が同じ Windows-31J の文字に置き換える。書けない文字は一覧で返す
- `index.html`
  - 1段目（たたんでも残る帯）に「読書／編集」と「保存」。狭い画面では書名を隠す
  - 編集面は `contenteditable="plaintext-only"`。改行・貼り付けは文字の改行として入るので、本文は文字列としてそのまま読める。`<br>`・`<div>` が混じるブラウザでも行として数える
  - 色付けは CSS Custom Highlight API（`::highlight()`）。本文の DOM を書き換えないので、入力・IME・取り消し（Ctrl+Z）を邪魔しない。入力が止まって 0.12 秒後、変換確定後に計算し直す
  - 開くとき：使えるブラウザでは `showOpenFilePicker`・ドロップの `getAsFileSystemHandle`・`launchQueue` からファイルの持ち手を受け取り、上書きに使う
  - 保存：Ctrl+S でも可。未保存のまま別ファイルを開く・文字コードを変える・閉じるときは確認
  - ファイル以外のドラッグ（編集中の文字の移動）は、ファイル読み込みの処理が横取りしないようにした
- `sw.js`：`edit.js` を同梱、版を v4 に

## 確認したこと

- `node tests/edit.test.js`（12件）・`node tests/md.test.js`（19件）すべて通過
- Chrome（実ブラウザ）で：段落内の追加・削除・新しい段落の色分け、横書き・縦書き、読書に戻したとき原文のままで ● が出ること、取り消し、保存後に色が消え読書表示に反映されること、2回目は同じファイルへの上書きになること
- Shift_JIS＋CRLF のファイルを編集して保存 → Shift_JIS と CRLF・末尾改行が保たれる
- `♡` を入れて Shift_JIS で保存 → 確認が出て UTF-8 で保存
- BOM 付き UTF-8 の .md をダウンロードで保存 → BOM が保たれる
- スマホ幅（375px）で、たたんだ帯に「読書／編集・保存」が残る

## 残っていること
